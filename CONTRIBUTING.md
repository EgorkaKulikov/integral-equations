# Правила изменения integral-equations

Репозиторий содержит решатели интегральных уравнений на языке Kotlin для платформы JVM.
Приведённые ниже правила распространяются на любое изменение кода и документации.

## Язык

Комментарии, KDoc, сообщения об ошибках, документация и сообщения коммитов пишутся
на русском языке; идентификаторы в коде — на английском. Сложившаяся конвенция отличается
от принятой в библиотеках `numerical-core` и `minimal-splines`, где тексты переведены
на английский язык. Изложение описательное: без слов заглавными буквами, без жаргона,
без ссылок на историю правок.

## Структура репозитория

Наборы исходников разделены по назначению: `main` — решатели
(`solvers/{core,fredholm,volterra,uryson}`), `test` — тесты и численные гейты,
`problems` — модельные задачи и аналитические фикстуры, `demo` — таблицы сходимости
и точки входа, `benchmark` — измерение производительности. Наборы `main`, `problems`,
`demo` и `benchmark` собираются в режиме `explicitApi()`, поэтому видимость каждого
объявления указывается явно.

Сплайны, аппроксимационные функционалы, квадратура, линейная алгебра и контекст вычислений
приходят из библиотек `minimal-splines` и `numerical-core` и подключаются только как
опубликованные артефакты. Зависимости вида `project(":…")` и `files("../…")` запрещены;
их отсутствие проверяет задача `verifyArtifactDependencies`, входящая в `check`.
Изменение, относящееся к сплайнам или численной инфраструктуре, выполняется в
соответствующей библиотеке с последующим обновлением версии в `gradle.properties`.

## Команды

    ./gradlew fastTest                   # набор с тегом fast: 142 теста, единицы секунд
    ./gradlew slowTest                   # набор с тегом slow: 23 теста, около 8.5 минут
    ./gradlew scipyVerify                # набор с тегом scipy: 9 тестов, требует окружения Python
    ./gradlew setupScipyVerification     # создание окружения Python для сверки со SciPy
    ./gradlew characterizationTest extraCharacterizationTest   # гейты численной нейтральности
    ./gradlew convergenceOrderTest       # полная матрица порядков сходимости, 168 сочетаний
    ./gradlew check                      # все перечисленные гейты и порог покрытия, около 9 минут

Задача `check` состоит из `fastTest`, `characterizationTest`, `extraCharacterizationTest`,
`slowTest`, `verifyArtifactDependencies` и `koverVerify`. Полный справочник по задачам,
машинно-зависимым гейтам и непрерывной интеграции приведён в `docs/TESTING.md`.

## Теги тестов

Каждый тестовый класс несёт ровно один тег времени выполнения: `fast`, `slow` или `scipy`.
Класс без такого тега не попадает ни в один набор и потому никогда не выполняется, а класс
с двумя тегами выполняется дважды. Соглашение проверяется сторожевым тестом
`conventions.TagConventionTest` по скомпилированным классам; допускается расстановка тега
как на классе, так и на каждом тестовом методе.

## Численные эталоны

Значения в `baseline-eh.tsv` (1366 ключей) и `baseline-extra.tsv` (1344 ключа) изменяются
только по протоколу, описанному в `docs/baseline-changes.md`: снимок до изменения,
снимок после, попарное сравнение ключей и запись в том же документе со старыми и новыми
значениями и причиной. Коммит с эталоном отделяется от коммита с изменением кода.
Подгонка допусков ради успешной сборки не допускается.

Эталон `published-values.tsv` (708 опубликованных чисел) не правится руками вовсе:
он порождается из .tex-таблиц статьи скриптом `tools/parse_published_values.py`,
который воспроизводит файл побайтово; порядок запуска описан в `docs/TESTING.md`.

## Покрытие

Порог покрытия — 67 % строк и 72 % ветвей — проверяется задачей `koverVerify` в составе
`check`. Источником покрытия служит только `fastTest`, поэтому пороги измерены для него;
изменение, опускающее покрытие ниже порога, проваливает сборку.

## Документация и коммиты

После изменения поведения решателей обновляются `README.md` и соответствующий документ
каталога `docs`. Новый численный метод сопровождается ссылкой на первичную публикацию
в `docs/REFERENCES.md` с указанием статуса; при отсутствии источника это указывается явно.
Сообщения коммитов пишутся на русском языке с префиксом области: `api:`, `algo:`, `test:`,
`docs:`, `build:`, `ci:`. Одному изменению соответствует один коммит.
